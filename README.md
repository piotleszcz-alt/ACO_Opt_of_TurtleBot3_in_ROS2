# ACO Path Planner for TurtleBot3 (ROS 2 Jazzy + Gazebo)

A mobile robot finds its own way through a map: an **Ant Colony Optimization (ACO)** planner searches for a path on an occupancy grid, and a **pure pursuit** controller drives a simulated TurtleBot3 along it in Gazebo. Start and goal are clicked in RViz2.

The project works on two maps:

- **Arena** – the standard TurtleBot3 world with 9 pillars (open space, easy routes),
- **Maze** – a generated maze with dead ends, where the ant colony really has to learn.

## How it works

```
map.yaml + map.pgm ──> MapData ──> obstacle inflation ──> ACO planner ──> path (cells)
                                                                              │
RViz2 clicks (start, goal) ──> aco_node ─────────────── /planned_path (metres) ┘
                                                              │
                               /odom (Gazebo) ──> pure_pursuit ──> /cmd_vel ──> robot
```

| Node | Subscribes | Publishes |
| --- | --- | --- |
| `aco_node` | `/initialpose` (`PoseWithCovarianceStamped`), `/goal_pose` (`PoseStamped`) | `/custom_map` (`OccupancyGrid`, transient local), `/planned_path` (`Path`) |
| `pure_pursuit` | `/planned_path` (`Path`), `/odom` (`Odometry`) | `/cmd_vel` (`TwistStamped`) |
| `static_transform_publisher` | – | TF `map → odom` (robot spawn pose) |

1. `aco_node` loads the map, inflates obstacles by the robot radius and publishes the grid to RViz2.
2. **2D Pose Estimate** in RViz2 sets the start, **2D Goal Pose** sets the goal.
3. The ACO planner computes a path on the grid; it is converted to metres and published on `/planned_path`.
4. `pure_pursuit` follows the path at 20 Hz using the robot pose from `/odom`.

## Installation

The launch file and the maze profile expect the workspace at `~/ros2_ws`. If you use a different location, update `PKG_SRC` in `launch/aco_sim.launch.py` and the maze map path in `aco_planner/config.py`.

```bash
mkdir -p ~/ros2_ws/src
cd ~/ros2_ws/src
git clone <this-repository-url> aco_planner

cd ~/ros2_ws
source /opt/ros/jazzy/setup.bash
rosdep install --from-paths src --ignore-src -y
colcon build --packages-select aco_planner --symlink-install
source install/setup.bash
```

With `--symlink-install`, changes to `.py` files take effect after restarting a node. Rebuild only after changing `setup.py`, `package.xml` or launch files.

### Generate the maze (once)

```bash
cd ~/ros2_ws/src/aco_planner
python3 make_maze.py
```

This writes `maps/maze/` with `maze.pgm`, `maze.yaml`, `maze.world`, `maze_world.launch.py`, `maze_preview.png` and `maze_info.txt` (start/goal coordinates, commands, shortest path lengths). The map and the Gazebo world are built from the same list of walls, so they always match.

Options: `--rows`, `--cols`, `--cell` (corridor pitch, m), `--thick`, `--height`, `--res`, `--robot-radius`, `--seed`, `--out`. If you change the maze, update the spawn pose `x`, `y` in `WORLDS['maze']` in the launch file using `maze_info.txt`.

## Running the simulation

```bash
cd ~/ros2_ws && source install/setup.bash

ros2 launch aco_planner aco_sim.launch.py                            # arena + Gazebo
ros2 launch aco_planner aco_sim.launch.py world:=maze                # maze + Gazebo
ros2 launch aco_planner aco_sim.launch.py world:=maze gazebo:=false  # planning only, RViz2
```

In RViz2:

1. Wait until the map and the robot are visible.
2. **2D Pose Estimate** – click on the robot (the start must be on a free cell of the inflated map).
3. **2D Goal Pose** – click the goal. Planning takes a few seconds; then the green path appears and the robot starts driving.

Only the press position matters; the drag direction (orientation) is ignored by the planner.

## Running without ROS (algorithm only)

`main.py` loads the map of the selected profile, shows the classification and inflation, then runs either a single plan or the tuning:

```bash
cd ~/ros2_ws/src/aco_planner
python3 -m aco_planner.main
```

- `config.PROFILE` – `"arena"` or `"maze"`,
- `config.RUN_TUNING = False` – one run with plots of the path, pheromone map and convergence,
- `config.RUN_TUNING = True` – `tuning.run_tuning`: every scenario × several seeds, a summary table and plots.

## Configuration

### Profiles (`config.py`)

| Parameter | Arena | Maze | Meaning |
| --- | --- | --- | --- |
| `alfa` (α) | 1.0 | 3.0 | pheromone weight |
| `beta` (β) | 5.0 | 2.0 | heuristic weight (pull towards the goal) |
| `q_0` | 0.95 | 0.7 | share of greedy moves (exploitation) |
| `max_iter` | 30 | 60 | iterations |
| `lam` (λ) | 0.2 | 0.0 | turn penalty in the path cost |
| `ants_per_px` | 0.25 | 0.25 | ants per pixel of straight-line distance |
| `ants_min` | 10 | 20 | minimum number of ants |
| `steps_factor` | 4 | 15 | step limit = factor × straight-line distance |

Common defaults: `rho` = 0.15, `Q_const` = 100, `tau_min` = 0.05, `tau_max` = 5.0, `tau_0` = 1.0. `ROBOT_SAFE_RADIUS` = 0.2 m (inflation radius).

### Node parameters

| Node | Parameter | Default | Meaning |
| --- | --- | --- | --- |
| `aco_node` | `map_yaml` | – (required) | path to the map YAML |
| `aco_node` | `profile` | `arena` | profile from `config.PROFILES` |
| `pure_pursuit` | `lookahead` | 0.2 m | look-ahead distance L_d |
| `pure_pursuit` | `v` | 0.15 m/s | forward speed (Burger max ≈ 0.22) |
| `pure_pursuit` | `goal_tolerance` | 0.1 m | stop distance |
| `pure_pursuit` | `max_omega` | 1.5 rad/s | angular speed limit |
| `pure_pursuit` | `odom_offset_x`, `odom_offset_y` | −2.0, −0.5 | robot spawn pose in `map` (odom → map) |

## Algorithm overview

### Map preparation

- Occupancy probability from pixel value v: $p = (255 - v)/255$; $p > 0.65$ → obstacle, $p < 0.196$ → free, otherwise unknown (treated as obstacle).
- The image is flipped (`np.flipud`) so that row 0 is the bottom of the map, where `origin` lies.
- Cell ↔ metres: $c = \lfloor (x - o_x)/res \rfloor$, $x = o_x + (c + 0.5)\,res$ (cell centre).
- Obstacles are dilated with a circular mask of radius $\lceil r/res \rceil$ px, so the robot can be planned as a point.

### Ant Colony Optimization (ACS decision rule + MMAS pheromone update)

For each step an ant at cell *i* looks at its 8 free, unvisited neighbours *j*:

- **Heuristic:** $\eta_{ij} = 1 / (c_{ij} + d_E(j, G))$, with step cost $c_{ij} \in \{1, \sqrt{2}\}$ and Euclidean distance to the goal.
- **Attractiveness:** $a_{ij} = \tau_j^{\alpha}\,\eta_{ij}^{\beta}$.
- **Decision:** with probability $q_0$ pick the most attractive neighbour, otherwise roulette selection with $P_{ij} = a_{ij} / \sum_l a_{il}$.
- **Dead ends:** the ant backtracks one cell instead of dying (needed in the maze).
- **Path cost:** $J = L + \lambda \sum |\Delta\theta|$ (length plus turn penalty).
- **Pheromone (global best, MMAS):** evaporation $\tau \leftarrow (1-\rho)\tau$, deposit $Q/J_{best}$ on the best path, clipping to $[\tau_{min}, \tau_{max}]$.

Heuristic and $\tau^{\alpha}$ are precomputed for the whole map (once and once per iteration), which makes the planner about 3× faster with identical results.

### Pure pursuit

The target point at distance $L_d$ on the path is transformed into the robot frame $(x_r, y_r)$; the arc through it has curvature $\kappa = 2y_r / L_d^2$ and the angular velocity is $\omega = v\,\kappa$. If the target is behind the robot it turns in place first.

## Tuning results

Parameters were tuned one at a time with fixed seeds, comparing against the straight-line distance (arena) and the true shortest path computed by `make_maze.py` (maze).

| Map | Result | Key findings |
| --- | --- | --- |
| Arena | paths ≈ 10 % above the straight-line lower bound, ≈ 1.3 s for the longest route | greedy settings win (q₀ = 0.95, β = 5); α = 0 gives the same result as α = 1 – pheromone barely matters |
| Maze | from 2.4–2.8× to 1.16–1.23× the shortest path (100 iterations) | pheromone is essential (α = 0 → 2.6–3.1×); optimum at q₀ = 0.7 and α = 3; a lower β helps because the straight-line heuristic points into walls |

The same algorithm needs opposite settings on an easy and a hard map, which is the main takeaway of the project.

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| Map not visible in RViz2 | Fixed Frame must be `map`; set *Durability Policy: Transient Local* on the Map display's **Topic** (not *Update Topic*) |
| Robot not visible in RViz2 | run RViz2 with `use_sim_time:=true`; RobotModel topic `/robot_description` with Transient Local |
| Path shifted relative to the robot | spawn pose in the launch file does not match Gazebo; check `ros2 run tf2_ros tf2_echo map base_footprint` |
| "Point is on an obstacle" when clicking | the inflated map is narrower than it looks; click in the middle of a corridor |
| No ant reaches the goal | `max_steps` too small – increase `steps_factor` in the profile's scaling |
| RViz2 freezes at start (WSL) | a saved default config with a Map display; move `~/.rviz2` away and/or run `LIBGL_ALWAYS_SOFTWARE=1 rviz2` |
| `Package 'aco_planner' not found` | `source install/setup.bash` in this terminal |
| `FileNotFoundError` for the maze map | relative path – use absolute paths in `config.py` |

Useful commands: `ros2 node list`, `ros2 topic echo /cmd_vel --once`, `ros2 topic info -v /custom_map`, `ros2 interface show nav_msgs/msg/Path`.

## Limitations and future work

- ACO is approximate: maze paths stay ~16–23 % longer than optimal and contain small zigzags; a **path shortcut / smoothing** step would remove most of them.
- Planning runs inside the subscriber callback and blocks the node for a few seconds; a separate thread or `MultiThreadedExecutor` would keep it responsive.
- `map → odom` is a fixed transform from the spawn pose; **AMCL** localisation would handle odometry drift.
- The start is clicked manually; it could be taken from the current robot pose.
- Pure pursuit cuts corners slightly; a regulated variant (slowing down in curves) would add safety margin near walls.
